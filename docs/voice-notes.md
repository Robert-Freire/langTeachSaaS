# Voice Notes — Recording, Transcription, Analysis

**Last updated:** 2026-05-05
**Status:** Living document. Update when the upload boundary, transcription provider, or extraction pipeline changes.

This document covers what happens when a teacher records audio in the app: where the audio lands, how it becomes text, and when (and how) that text is analysed by an LLM.

---

## 1. End-to-End Flow

```
Teacher records (browser mic, MediaRecorder)
  │
  │ multipart POST /api/voice-notes
  ▼
VoiceNotesController.Upload                         (Controllers/VoiceNotesController.cs)
  │ • RequestSizeLimit 51 MB
  │ • file name and content type length checks
  ▼
VoiceNoteService.UploadAsync                        (Services/VoiceNoteService.cs)
  │ 1. Strip codec params from MIME (e.g. "audio/webm;codecs=opus" -> "audio/webm")
  │ 2. Validate against AllowedContentTypes (webm, mp4, mpeg, wav, ogg)
  │ 3. Buffer stream in memory
  │ 4. Magic-byte check vs declared MIME (anti-spoofing)
  │ 5. Upload buffer to Azure Blob Storage (container "voice-notes")
  │ 6. Transcribe buffer
  │ 7. Persist VoiceNote row (BlobPath + Transcription + TranscribedAt)
  ▼
Returns VoiceNoteDto to the frontend
```

After upload, the audio lives in blob storage and the transcript lives on the row. **No analysis runs at this point.** Analysis happens only when the teacher applies the note to a session (see §4).

## 2. Storage

### 2.1 Blob: raw audio

- **Container:** `voice-notes` (separate from the `materials` container used for lesson PDFs/images).
- **Path:** `teachers/{teacherId}/{voiceNoteId}{ext}`. The file extension is preserved from the original upload.
- **Created at startup:** `VoiceNoteBlobStorage.InitializeAsync` calls `CreateIfNotExistsAsync` (see `Program.cs` startup scope around line 242).
- **Download:** `GET /api/voice-notes/{id}/audio` issues an HTTP redirect to a 15-minute SAS URL generated by `VoiceNoteBlobStorage.GetDownloadUrlAsync`. SAS is generated only when the blob client supports it (Managed Identity / connection string with key); otherwise the bare blob URI is returned. There is no "rehydrate the audio" endpoint that proxies bytes.

### 2.2 Database: `VoiceNote`

`backend/LangTeach.Api/Data/Models/VoiceNote.cs`

| Column | Notes |
|--------|-------|
| `Id` (Guid, PK) | Same id used in the blob path. |
| `TeacherId` (FK) | Owner. All queries filter by this (multi-tenancy invariant). |
| `BlobPath` | `teachers/{teacherId}/{id}{ext}`. |
| `OriginalFileName`, `ContentType`, `SizeBytes` | As declared by the client, after MIME parameter stripping. |
| `DurationSeconds` | **Reserved, always 0.** Duration extraction is not yet implemented. |
| `Transcription` (nullable) | DisplayText returned by Azure Speech, or `null` if transcription failed and the row was retained. |
| `TranscribedAt` | Set when transcription succeeds. |
| `CreatedAt` | Upload time. |

The row is the only persistent representation of the transcript. Editing the transcript: `PATCH /api/voice-notes/{id}/transcription`.

## 3. Transcription

### 3.1 Provider: Azure AI Speech (Speech-to-Text REST, simple recognition)

`backend/LangTeach.Api/Services/AzureSpeechTranscriptionService.cs`

Configuration:

- Endpoint: `https://{Region}.stt.speech.microsoft.com/speech/recognition/conversation/cognitiveservices/v1?language={Language}&format=simple`
- Options: `AzureSpeech:ApiKey`, `AzureSpeech:Region`, `AzureSpeech:Language` (`AzureSpeechOptions.cs`). Both ApiKey and Region are required at startup.
- Constraints: simple recognition is capped at ~60 s per request. The service rejects converted audio over **10 MB of PCM WAV** (16 kHz / 16-bit / mono ≈ 1.92 MB per minute).

### 3.2 Pre-processing: ffmpeg

The service does not send the original webm/mp4/etc. to Azure. It pipes the buffered audio through `ffmpeg -i pipe:0 -ar 16000 -ac 1 -f wav pipe:1`, producing 16 kHz mono PCM WAV. Azure's simple recognition endpoint is most reliable on this format. ffmpeg must be on the container PATH (it is in the API image).

The conversion runs in-process: stdin write, stdout copy, and stderr drain run concurrently to avoid pipe-buffer deadlock. On non-zero exit, stderr is logged and the upload fails with `"Audio conversion failed."`.

### 3.3 Stub for local dev

`StubTranscriptionService.cs` is registered when configured (see `Program.cs:167-169`). Use it to develop without burning Azure Speech credits. Selection is by configuration, not env-name; read `Program.cs` for the current toggle.

### 3.4 Failure modes

| Failure | Effect |
|---------|--------|
| ffmpeg exits non-zero | `InvalidOperationException("Audio conversion failed.")`, request returns 400. **No row written, no blob retained** (blob upload precedes transcription, but the service throws before persistence — see note below). |
| Converted WAV > 10 MB | Same path as ffmpeg failure (rejected with size message). |
| Azure Speech non-2xx | `InvalidOperationException("Transcription failed: {status}")`. |
| `RecognitionStatus != "Success"` | `InvalidOperationException` with the returned status string. |

**Known wart:** the blob is uploaded *before* transcription runs (`VoiceNoteService.cs:94` then `:99`). If transcription throws, the blob is left in storage with no DB row pointing at it. There is no orphan-cleanup job. Track this if storage cost ever matters.

## 4. Analysis (LLM extraction)

The raw `VoiceNote` is just blob + transcript. **There is no automatic LLM pass on upload.** Analysis happens in two places, and only against the transcription text (the audio itself is never sent to Claude).

### 4.1 ReflectionExtractionService

`backend/LangTeach.Api/Services/ReflectionExtractionService.cs`

Builds a prompt via `IPromptService.BuildReflectionExtractionPrompt` and calls Claude (Haiku-class — see PromptService for the exact model). Output: `ExtractedReflectionDto` with structured fields the teacher can apply to a session (what was covered, areas to improve, emotional signals, homework, suggested difficulties, session title, topic tags, duration, level reassessment, follow-ups, etc.).

Three controllers invoke the extraction:

| Controller | Endpoint | Purpose |
|------------|----------|---------|
| `LessonNotesController` | `POST /api/lesson-notes/extract` | Extract from free-text lesson notes (no session context). |
| `SessionsController` | `POST /api/sessions/extract` | Extract for an open session, with `knownDifficulties` context. |
| `AssistantController` | `POST /api/assistant/propose` | Run student-profile extraction and reflection extraction in parallel for the Atelier panel. |

The frontend pattern is: upload audio → read `transcription` from the returned `VoiceNoteDto` → call one of the `*/extract` endpoints with that text. The voice-note flow is therefore "audio in, two API calls out": one to transcribe, one to extract.

### 4.2 VoiceNoteApplication (audit trail)

When the teacher applies extracted fields to a `SessionLog`, `SessionLogService` writes a `VoiceNoteApplication` row (`SessionLogService.cs:151`) capturing:

- `SessionLogId` — which session received the data.
- `VoiceNoteId` — nullable (free-text reflections have no underlying voice note).
- `Transcription` — verbatim text the user applied (may differ from `VoiceNote.Transcription` if the teacher edited it).
- `RawExtractionJson` — the full LLM response that was applied.
- `ApplicationType`, `AppliedAt`.

This row exists so we can later answer "where did this session-log field come from?" and so the session-list view can show a "has voice note" badge (`SessionLogService.cs:56,72`).

### 4.3 Telegram path

`TelegramConversationService.cs` ingests text from a Telegram bot (no audio: Telegram sends text already). It runs the same `ReflectionExtractionService.ExtractAsync` and writes the same `VoiceNoteApplication` rows (with `VoiceNoteId = null`). Treat Telegram as "voice-less voice notes" semantically.

## 6. Configuration & Secrets

Required `appsettings` / Key Vault keys:

- `AzureSpeech:ApiKey` (validated at startup)
- `AzureSpeech:Region` (validated at startup)
- `AzureSpeech:Language` (defaulted by `AzureSpeechOptions`)
- Blob connection string (shared with materials, resolved by the `BlobServiceClient` registration in `Program.cs`)

Voice-note storage adds **one extra blob container** (`voice-notes`) on top of the `materials` container described in `architecture-model.md §2`. There is no separate storage account.

## 7. Invariants

| # | Invariant | Enforced by |
|---|-----------|-------------|
| V1 | Audio is owned per teacher; no cross-teacher reads. | All `VoiceNoteService` queries filter on `TeacherId`. |
| V2 | Audio bytes never reach Claude; only transcribed text does. | `ReflectionExtractionService.ExtractAsync(string text, ...)` signature. The Anthropic call site has no audio path. |
| V3 | Allowed MIME set = {webm, mp4, mpeg, wav, ogg}. | `AllowedContentTypes` constant + magic-byte validators in `VoiceNoteService`. |
| V4 | Audio download is short-lived. | 15 min SAS in `VoiceNoteBlobStorage.GetDownloadUrlAsync`. |
| V5 | Transcript edits are explicit. | `PATCH /api/voice-notes/{id}/transcription` is the only mutation path. |
| V6 | Application of extracted data to a session is auditable. | `VoiceNoteApplication` row written in `SessionLogService.UpdateAsync` whenever `VoiceNoteId`, `VoiceNoteTranscription`, or `RawExtractionJson` is present in the request. |

## 8. Open Items / Known Gaps

- **Orphan blobs on transcription failure** (§3.4). Acceptable today; revisit if storage cost grows.
- **`DurationSeconds` is always 0.** Reserved column. If/when surfaced in UI, populate it from ffprobe during the ffmpeg step rather than relying on the client.
- **60 s simple-recognition cap.** Long teacher debriefs need to be broken up by the user or migrated to the batch / continuous-recognition endpoint. There is no chunking on the server today.
- **No retention policy** on `voice-notes` container or `VoiceNote` rows. Data accumulates forever until manual cleanup or teacher delete (`DELETE /api/voice-notes/{id}` removes the blob and row).
